# Security model

Educational analysis of synthetic assertions only. Neither conditional order nor known UTC syntax authenticates a timestamp, measures accuracy, establishes causation or proves a complete timeline. This is not a production forensic tool or malware sandbox.

Addressed threats: hostile JSON resource/identity/type ambiguity, contradictory provided assumptions hidden behind unknown context, unsupported timestamp normalization, report injection, clobbering/partial file output and misleading chronological conclusions. Strict schema/data-only parsing, predecode limits, complete pair enumeration, conservative integer envelopes, escaped output and exclusive publication address these within the documented model.

Trust Python/source, regular local input files and the output directory. No real logs, private host/account/command data or employer/client evidence belongs in fixtures. Fields marked synthetic are user claims, not an automatic privacy filter. Special devices, hostile directory races, filesystem faults and power-loss durability are not contained. Stdout failure can leave partial output; diagnostics are fixed/redacted when stderr works.

No network, clock/NTP, registry/log APIs, services or user-selected execution in the analyzer. Verification is trusted-code execution of fixed local tests/scripts and intentional isolated regressions, not parsing untrusted executable code. Bandit was already installed and not upgraded. No broad SAST suppressions or runtime third-party dependencies.

Findings are reviewed locally with Jake. No hosted disclosure channel, remote publication or external messaging is configured/authorized. Passing tests/self-review are evidence within scope, not a proof of safety or actual host accuracy.
